# weekly-git-report

## 作用

根据 Git 提交自动生成本周周报的对外汇报文案（中文、有序、简洁）。

## 步骤

1. 查询本项目的 git 本周（周一到周五）的提交信息
   - 如果commit message 太模糊，你要去查看提交了什么文件，然后看看实现了什么功能（拆成原子的功能）
2. 将提交结果压缩为原子任务（保留顺序）。
3. 输出汇报文本。

## 输出要求

1. 中文序号格式：`一、二、三…`
2. 每条一句话，聚焦“完成了什么，解决了什么”
3. 不编造、不过度展开技术细节

## 输出模板

```text
本周完成的工作：
一、搭建迁移任务工作空间隔离机制，避免多任务并发时的资源互扰与状态污染。
二、补充项目背景与需求说明文档，统一需求口径并完善交付前说明材料。
二、整理并形成 Bifrost 在线迁移原理汇报大纲，明确迁移架构与关键流程。
四、修复 Linux 驱动注入日志路径，保障迁移日志可定位、可追踪、可排障。
五、修正目标虚拟机启动固件映射配置，消除迁移后因固件参数不匹配导致的启动异常。
六、优化 FC 系统模板映射逻辑，提升操作系统与模板匹配的正确性与兼容覆盖。
七、新增 FusionCompute OS 版本选择能力，实现按目标系统版本的细粒度迁移配置。
八、实现 cutover 就绪状态的 WebSocket 推送，支持前置割接动作的实时可观测。
九、重构任务 OS schema 迁移流程为 SQLite 安全实现，降低数据库并发和一致性风险。
十、补充 Kylin/Euler 驱动注入实施方案文档，明确适用边界、处理规则与风险说明。
十一、增强 Kylin/Euler 驱动注入兼容性与稳定性，覆盖关键注入场景并修复相关缺陷。
十二、调整驱动注入策略为“跳过内置 virtio驱动注入”，避免重复注入引发的冲突与迁移失败。
```

## 多项目场景的结构规范

当用户同时维护 **多个项目/平台** 时（例如迁移平台 + 网规平台），不要混在一起写成一条长列表，必须按以下结构组织：

1. **先按项目/平台分块**：每个项目作为一级标题（`一、二、三…`）。
2. **项目内部用数字列表**：`1. 2. 3.`。
3. **同类事情合并成一条**：不要把拆成十几条细碎 commit 的同一模块工作写成 10 条，要压缩为 1-3 条“大白话”总结。
4. **总条目控制在 8 条以内**（所有项目加起来）。

### 示例 A：两个平台都有开发

```text
本周完成的工作：
一、迁移平台
1. 准备软著申请材料，整理源码文档与注册授权文件（公私钥、许可证、注册库）。
2. 调整迁移超时策略：关机超时支持 0 表示无限等待，放宽 Windows 驱动注入和磁盘检测的超时限制。

二、网规平台
1. 规划设计 V2 从零搭建：从领域模型设计、proto 定义、存储模型建表，到创建/列表/删除/详情全链路接口落地。
2. 规划数据流转打通：实现规划数据到 LLD 的装配与导出，完成主模板渲染；命令配置导出对齐 V1（含选实现、插槽、递归子模板、引擎）。
3. 业务模型重构：拆出独立的 Business 资源并配套 CRUD 接口和字段校验，LLD 与数据查询维度从 project 切到 business。
4. 机房 U 位概览接口落地，设备配置导出时逐台收集错误并汇总返回。
5. 部署与文档：新增 test 环境部署流水线，调整 nacos namespace 复用老库基础数据；补充领域模型设计文档。
```

### 示例 B：单一项目但多模块并行

```text
本周完成的工作：
一、用户中心模块
1. 完成用户注册/登录接口，接入企业微信扫码授权。
2. 统一 JWT 签发与校验逻辑，替换旧版 session 方案。

二、订单模块
1. 实现订单创建与支付回调，支持支付宝和微信支付。
2. 补充订单状态机与超时自动取消机制。

三、基础设施
1. 搭建 CI/CD 流水线，完成测试环境自动部署。
2. 接入 Prometheus + Grafana 监控，覆盖核心业务指标。
```

### 示例 C：偏行政/非代码类工作为主

```text
本周完成的工作：
一、产品交付
1. 整理 V2.3 版本更新说明，输出用户升级手册。
2. 与客户对齐验收清单，确认 3 项遗留问题排期。

二、团队建设
1. 组织代码评审规范培训，统一 Go 项目编码风格。
2. 补充新人入职指引文档，覆盖开发环境搭建与常用命令。
```
